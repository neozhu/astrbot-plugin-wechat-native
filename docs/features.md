# 功能使用指南

[返回 README](../README.md) · [部署与配置](../README.md#安装与配置)

## 面板扫码登录与连接通知

Native v2.3.0 账号未认证时，打开插件的 **WeChat Native 面板**，选择已启用的机器人，
扫描二维码并在手机微信确认；任务失败或过期后点击“重新获取二维码”。
管理凭据沿用 `admin_token_file`，详细前提见[运维说明](operations.md#面板扫码登录与跨平台告警native-v230)。

在已接入 AstrBot 的目标平台**管理员私聊**发送 `/绑定通知 [native_bot_id]`，
再用 `/测试通知 [native_bot_id]` 确认接收端是否收到。只有一个启用的 Native 实例时可省略 ID。
`/通知状态` 查询最近监控状态，`/解绑通知` 移除接收目标。
英文等价命令为 `/bind_alert`、`/test_alert`、`/alert_status`、`/unbind_alert`。
每次事故最多尝试一次断线和一次恢复通知；平台调用成功不等于实际送达。

## 微信好友管理（Native v2.7.1）

在目标机器人的配置中开启 `enable_friend_requests`（默认关闭）。此功能从 Native v2.7.1 起可用。
搜索、查询及订阅使用现有的 `read` 凭据；发送和接受使用 `admin_token_file` 中对该账号有
`admin` 权限的凭据。AstrBot 4.29.3 的主 Agent 请求钩子只在已启用功能的 WeChat Native 管理员私聊保留以下工具的 Schema。

| AI 工具 | 用法 |
| --- | --- |
| `wechat_search_contact` | 按确切微信号搜索，返回显示名称、好友关系及可用的短时 `recipientRef` |
| `wechat_list_contacts` | 每页查询最多 12 条本地联系人。默认只看已确认的好友，也支持 `all`、`non_contact`、`unknown` |
| `wechat_send_friend_request` | 管理员明确指定要添加的人后，使用同一账号的搜索引用提交，可附验证消息 |
| `wechat_list_friend_requests` | 查询待处理的收到的好友申请，可按姓名筛选。遍历 Native 分页，最多展示 12 条 |
| `wechat_accept_friend_request` | 按查询得到的申请 ID 接受，提交前获取当前版本。同名多条时需指定其中一条 |

例如在微信机器人私聊说“搜索微信号 alice123 并给她发送好友申请，验证消息写‘我是小李’”，
或说“查看待处理好友申请”“通过张三的申请”。搜索只读取资料。引用过期时请按微信号重新搜索。
若申请版本已变化，请重新查询。发送与接受使用幂等键，结果不明时只检查原 Operation。
收到“申请确认已提交”后请等待微信同步，好友关系确认后才会报告添加成功。
可以在私聊说“按微信号 alice123 查通讯录，确认是否已经是好友”。
联系人身份匹配且 `relation=friend` 表示本地已经确认好友关系。按 `nextCursor` 继续查询后续页面。
查询为空时，可能仍在等待同步。

在 Telegram、QQ、LINE、`weixin_oc` 或 WeChat Native 的 AstrBot 管理员私聊中执行：

| 指令 | 用途 |
| --- | --- |
| `/订阅好友 [native_bot_id]` 或 `/friend_subscribe [native_bot_id]` | 将新申请通知发到当前私聊 |
| `/好友订阅状态 [native_bot_id]` 或 `/friend_status [native_bot_id]` | 查询当前订阅渠道 |
| `/取消订阅好友 [native_bot_id]` 或 `/friend_unsubscribe [native_bot_id]` | 取消好友申请通知 |

只有一个启用的 Native 机器人时可省略 ID。有多个时，请按指令提示指定机器人 ID。
重复订阅会更新目标，每个机器人保留一个目标。好友订阅独立于断线通知，使用现有 SSE，
订阅指令和通知均无需模型。首次订阅时已有的申请不补发。同一申请最多尝试发送一次，
尝试记录和订阅在重启后保留。收到游标过期告警时，请检查 Native 事件保留历史与插件日志，
插件会保留原游标并停止接收。通知依赖接收平台的主动消息权限及有效会话。

## 链接卡片读取

文章、音乐和视频分享卡片会把标题、来源、链接和摘要交给 AstrBot。群聊遵循当前的触发模式和白名单，私聊遵循私聊回复设置。
开启 `enable_media` 时，插件通过 Native 获取卡片附带的封面，供支持视觉的模型读取。封面缺失、下载失败或超时仍会交付卡片文字。
当前聊天的历史读取和搜索返回卡片文本。插件只读取卡片本身提供的信息，不会打开链接页面或下载其音视频。

## 支持发送图片

表情应使用下面的[原生表情工具](#原生表情native-v240)，不会降级为普通图片发送。

AstrBot 的 `Image` 组件可发送到微信私聊和群聊，也支持通过已保存会话主动发送。
可使用 `Image.fromBytes(data)`、`Image.fromFileSystem(path)`、`Image.fromURL(url)`、
`Image.fromBase64(data)`、`Image.fromIO(stream)`，以及标准 `Image` 的本地路径、file URI、
base64 data URI 或裸 base64 来源；`url` 字段优先于 `file`，与 AstrBot 的接口一致。
支持 JPEG、PNG、GIF、WebP，**单张上限 10 MiB**；Native 负责后续图片处理，微信端显示效果需实际验证。

默认按 Native 的**标准画质**发送：插件只提交 `kind=image` 和 `sourceId`，不指定画质，
所以远端生成的标准副本会被压缩。开启 `image_quality_original`（默认关闭）后，
`/sends` 请求会带上 `imageQuality: "original"`：

* JPEG 源按原字节发送，不受分辨率限制；
* PNG、GIF、WebP 会在全分辨率下转为 JPEG，所以这个开关不能用来发动画（GIF 见下面的表情通道）；
* JPEG 原样发送时保留内嵌元数据，可能包含相机与位置信息。

该开关只影响发送，不改变接收与识别。视频画质不在本开关范围内。

### GIF 以微信表情发送

微信只把**贴纸通道**发来的内容渲染成表情气泡，普通图片通道的 GIF 会被压缩成静态图。
开启 `send_gif_as_sticker`（默认开启）时，GIF 改走 Native 的贴纸制备通道：

制备有硬性限制：最长边 1024、产物 1 MiB、200 帧、10 秒。聊天里的动图通常远超 1 MiB，
原样提交会被拒绝，所以 `gif_sticker_compression`（默认 `auto`）会先在本地把 GIF 压到限制内。
档位不是逐档试出来的：插件按源图的尺寸、帧数与时长，用实测的「每像素字节数」上限预测
每个候选档位的产物大小，直接选中第一个满足 1 MiB 的档位编码一次；只有在预测落空时才补一次
最小档位，不会沿档位阶梯反复重编码。如果最小的档位仍然超限（画面很碎、帧数又不多的 GIF 会这样），
`auto` 会先隔帧抽样再选档，代价是掉一些帧；`conservative` 不做这种抽样，这种 GIF 会回退普通图片。

* `auto`：五档 1024/512/320/240/160，可缩小画面、隔帧抽样与减色，优先保住动画；
* `conservative`：七档，只缩小画面和减少颜色，不抽帧、不改节奏，更完整但可能仍然超限；
* `none`：不压缩，只有本来就满足限制的 GIF 能变成表情。

时长不是简单隔帧抽样：每帧的延迟可以不同，插件让每张保留帧吸收被跳过帧的延迟，再整体按比例
缩放到 10 秒以内，所以长动图会略微加快播放而不是丢掉结尾；透明背景会合成到白底。

压缩在独立线程执行（最长 30 秒，峰值内存受单帧 16 Mi 像素的总量预算约束），并且只重编码超限的
GIF；本来满足限制的 GIF 原字节直传，Native 制备时不会重新编码。压缩或制备失败都不影响这条消息：
插件回退为普通图片发送。

发送顺序：

1. `POST /v1/accounts/{account}/uploads` 上传（压缩后的）字节，标识为 `image.gif`；
2. `POST /v1/accounts/{account}/sticker-preparations` 提交 `sourceId` 与 `maxEdge: 1024`，轮询直到
   `state=available`，确认产物 `original` 的 `contentType` 为 `image/gif`；上传的字节已不超过 1024，
   制备既不会缩边也不会重编码，产物与上传字节一致；轮询只重试读请求，已提交的制备不会被丢弃；
3. `POST /v1/accounts/{account}/sends` 提交 `kind=sticker` 与 `source: {kind: "prepared", preparationId}`。

任何一步失败（含制备被拒、任务超时、回执未确认）都回退为普通图片发送，并复用已上传的
`sourceId`，不会重复上传。关闭 `send_gif_as_sticker` 后 GIF 按普通图片发送，走上面的画质设置。

文本和图片按消息链顺序逐段发送，多张图片逐张确认后再发送下一张。例如：

```python
from astrbot.api.event import MessageChain
from astrbot.api.message_components import Image, Plain

await event.send(MessageChain([
    Plain("第一张图"),
    Image.fromFileSystem("/app/data/example.jpg"),
    Plain("第二张图"),
    Image.fromBytes(image_bytes),
]))
```

插件先通过 `POST /v1/accounts/{account}/uploads` 上传图片，再通过 `/sends` 提交
`kind=image`、`sourceId` 和 `Idempotency-Key`，不会把图片作为普通文件发送。
图片 job ID 会在轮询前保存到 SQLite。提交结果不明时只用原幂等键查询回执，
后续只查询原 job；不会自动重新上传、重发或换键重试。
失败、超时、断线、5xx 或未知状态会保留 `failed` / `needs_review` / `partial` 状态，
停止发送消息链剩余部分；已发送部分不会回滚，需检查微信和状态库后人工处理。

Native v1.4.0 的图片请求不接受引用和 @字段。混合消息链的显式引用、@和首段自动 @
由第一段非空文本承载；纯图片回复不自动 @。纯图片链若显式包含 `Reply` 或群 @，
需添加非空文本，否则插件在发送前报错。

URL 图片仅允许公网 HTTP(S) 和 80/443 端口，不携带 Native Token、Cookie 或环境代理。
连接时校验实际 DNS 地址，拒绝内网、环回、链路本地及其他非公网地址；最多跟随 3 次重定向，
每一跳重新检查。下载总超时 15 秒、连接及连续读取超时各 5 秒，流式限制 10 MiB，
拒绝压缩传输。内网图床请改为本地路径或 bytes 来源。

## 原生表情（Native v2.4.0）

采用“提前添加并下载 → 按描述查找 → 原生发送”的流程。在机器人参数中开启
`enable_stickers: true`，默认值为 `false`。沿用目标账号的 `read + media + send` 权限。

### 在私聊中准备表情库

先在机器人登录的手机微信账号中添加需要的表情包。将操作人员的微信 senderId 配置为
AstrBot 全局管理员，开启 `enable_stickers`，完整重启 AstrBot 后，私聊该机器人发送一条指令：

```text
/表情包同步
```

机器人先回复开始提示，自动等待 Saved 和已添加包目录同步完成，再逐个下载所有未就绪的已添加官方包。
已就绪包直接跳过，一个包失败后继续处理其他包，最后汇总下载成功、已就绪、失败及未完成数量。
失败或待核对项会附包 ID 和已保留的任务编号，最多列出10项。

此指令复用当前机器人的 Native 账号与 Token，直接调用 HTTP API，
无需进入终端或安装 CLI。只有 AstrBot 管理员的可信 WeChat Native 私聊可以使用，
群聊、普通用户或其他平台不会发起管理操作。权限来自 AstrBot 全局管理员配置，
不使用 `wechat_action_admins`。

只有 `/表情包同步` 一个管理指令，旧版的列表、单包下载、状态、帮助及英文别名已移除。
同一机器人同时只执行一个完整流程，重复发送会提示正在处理，结果由原流程自动回复。
每个任务最多自动等待五分钟；超时或回执不明确时如实报告未完成，不算作下载成功。
稍后仍可发送同一条指令：已就绪包跳过，在途任务只核对原回执；明确失败的包可重新尝试。
没有收到任务编号的未知结果保持阻塞，需检查 Native 原记录。重启只查询已保留任务；
如需继续余下包，重启后再次发送 `/表情包同步`。

此指令串联已有 Native 操作，不能修复 Native 下载服务自身的错误。
例如 `media_service_rejected` / HTTP 400 会计入失败，并继续下载其余包。

下载保存在 Native 自身缓存中，不导出到 AstrBot 文件夹，也不扫描本地素材目录。
账号成员关系与媒体就绪状态分别判断；下载不会自动添加表情包。
插件只发送其中已就绪的原始 GIF，未缓存、非 GIF 或身份不符的项不会成为发送候选。
准备操作不会将表情自动发到聊天，也不会恢复引用收藏功能。
具体资源行为见[官方表情包文档](https://thisnick.github.io/agent-wechat/use/stickers/)。

### 查找与发送

| 工具 | 用法 |
| --- | --- |
| `wechat_find_stickers(query="", limit=12)` | 从本地就绪的 Saved 与已添加官方包，按官方描述、包名及本地描述查找；不下载、不发送 |
| `wechat_send_sticker(selection_id)` | 在当前聊天发送当前事件选中的原生表情，发送前重新检查成员关系和 GIF 就绪状态 |

查找采用文字子串匹配，适合“开心”“晚安”“谢谢”等简短关键词；空查询返回可用候选。
缺少描述的已缓存 Saved 项，在开启 `enable_media` 且当前模型支持视觉时，可有界读取预览生成本地描述。
描述仅写入插件 SQLite，不修改微信或 Native 官方数据；未描述的图片不凭 ID 猜测含义。
官方包优先使用其官方描述与包名。

可在 AstrBot 的人格提示词中加入：

> 微信聊天中，可根据当前语境适量使用表情。先用 `wechat_find_stickers` 查询简短内容或情绪关键词，
> 从返回的描述中选择合适项，再用 `wechat_send_sticker` 发送当前消息的新 `selection_id`。
> 没有合适候选时继续正常文字回复。素材由管理员通过私聊指令提前准备；不要声称已下载或收藏表情。
> 发送结果为 `pending` 或 `needs_review` 时不重复发送。工具返回 `success/pending/needs_review` 后输出一句
> 简短结束语，插件会拦截该结束语外发。

发送使用 `/sends` 的 `kind=sticker` 及 Saved/pack 引用，保持原生微信表情格式。
每条触发消息最多一个表情，同群至少间隔30秒。`success` 表示 Native 已确认微信接受，
`pending` / `needs_review` 表示尚未确认。发送成功及待确认/未知发送结果都会停止本次触发的后续文本和语音回复。

候选保留5分钟，每个事件最多保留最近120个；单次查找最多读取前100个 Saved 和50个已添加官方包。
候选属于当前消息，下一轮请求需重新查找；`sticker_selection_expired` 表示尚未提交发送，可重新查询。
固定幂等键和回执保存在原 SQLite 中，重启只查询原操作。历史收藏操作仍保留只读回执核对，
插件不再提交引用收藏或群聊自动收藏请求。

### 引用表情视觉读取

引用微信普通表情或分享表情提问仍可读取预览；群聊需要真正 @机器人，并遵守群白名单。
视觉读取还需 `enable_media: true` 和支持视觉的模型。读取引用不会把该表情加入 Saved。

媒体优先从承载引用的回复消息读取；`missing` 引用可在核验同账号、同聊天、发送者、消息类型与未撤回状态后，
回退读取同聊天原消息。只访问 Native 的已验证资源；GIF 交付代表静态帧，不能据此声称理解完整动画。
无效、撤回、过期或无法解码的资源不会交给视觉模型。

输入框里的微笑、捂脸、旺柴等小黄脸是文字表情，Native 保留 `[微笑]`、`[捂脸]` 等别名，按文字交付。
历史测试与升级记录见[验收记录](verification-stickers-v2.4.0.md)，当前要求见
[SPEC](SPEC-WeChat%20Native%20Sticker%20Receive%20Save%20%20Send.md)。

## 微信语音收发

语音服务部署与配置见 [README：微信语音收发](../README.md#微信语音收发)。

**接收语音**使用现有 `enable_media` 开关（默认开启）。插件识别微信 `type=34`，
通过 Native Media API 获取 `normal` 变体，由 Native 将 SILK 解码为 **16 kHz、单声道、16 位 PCM WAV**。
校验账号、消息、资产身份、大小和 SHA-256 后，生成标准 AstrBot `Record`，
由 AstrBot 现有 ASR 流程识别；插件不调用特定语音服务，也不会把微信语音 XML 当作用户文字。

1. 在机器人所使用的 AstrBot 配置中开启**语音转文字/ASR**（`provider_stt_settings.enable`），
   并为该会话选择 ASR 提供商；也可使用能处理标准 `Record` 的 ASR 插件。
2. 私聊直接发送微信语音即可，仍遵守私聊开关和 `allowed_users`。
3. 默认 `mention` 群聊模式：先发语音，再由同一成员在 **2 分钟内真正 @机器人**发送
   `读取语音`，例如 `读取语音，转成文字`；也可引用语音并真正 @机器人自由提问，无需读取指令。
   普通群语音仅临时保存消息标识，不会提前下载或识别。
4. `all` 模式允许直接处理群语音；`disabled`、`allowed_groups` 和成员独立会话规则照常生效。
   引用语音仍要求真正 @机器人。引用原消息必须已记录在同一账号、同一聊天，其他成员的语音请明确引用。

没有配置 ASR 时，插件仍交付 `Record`，不会自行选择服务商或捏造转写结果；
AI 是否能理解音频取决于 AstrBot 的 ASR、插件或模型配置。群聊摘要仍只收集原有文本，不收集语音转写。
撤回会取消待处理任务；下载前后及发送回复前会检查来源身份和撤回状态。
媒体下载默认总超时 60 秒，接收的单条微信语音上限 60 秒；音频内容不写入插件 SQLite。
交付后的临时 WAV 由 AstrBot 标准媒体流程创建并管理。

**发送语音**支持 AstrBot TTS/插件产生的标准 `Record`：本地路径、file URI、
`Record.fromFileSystem(path)`、`Record.fromURL(url)`、`Record.fromBase64(data)`、
音频 base64 data URI 和裸 base64；遵循 `Record` 的 `file → url → path` 来源回退。
同一 AstrBot 内的 TTS 建议设置 `provider_tts_settings.use_file_service: false`，直接使用生成的本地音频路径。
例如：

```python
from astrbot.api.event import MessageChain
from astrbot.api.message_components import Plain, Record

await event.send(MessageChain([
    Plain("这是语音回复："),
    Record.fromFileSystem("/app/data/tts-output.wav"),
]))
```

插件先 `/uploads`，再 `/sends` 提交 **`kind=voice`**，发送原生微信语音，绝不降级为普通文件。
支持私聊、群聊、主动发送，以及与文本、图片混合的消息链顺序。
语音本身不支持 Native 引用/@字段；需要这些信息时在消息链中添加非空文本，由首段文本承载。
纯语音回复不自动 @；TTS 的 `Record.text` 只是附带元数据，不会额外重复发送成文字。

支持 Native 的 WAV、MP3、FLAC、Ogg、AAC、M4A/MP4、WebM 和 SILK 来源，
容器内音频编码能否解码由 Native 判断。**每个来源最多 26,214,383 字节、总长 300 秒**；
Native 负责格式转换和内置 SILK 编码，并将超过 60 秒的音频拆为尽量等长、每条不超过 60 秒的微信语音。
建议在 **Native 所在主机/容器**安装 FFmpeg，以处理压缩音频及其他采样格式；
16 kHz 单声道 PCM16 WAV 和支持的 SILK 可使用 Native 内置处理路径。插件不自行切片或重复编码。

一个 `Record` 对应一次上传、一个幂等键和一个 Native job，默认最多等待 25 分钟。
逐段 `index/state/durationMs/serverMessageId` 回执存入 SQLite 的 `send_chunks`，
与原 `sends` 表的 job ID 关联；旧文本和图片状态无需迁移或清空。
长语音部分成功后发生失败、超时、断线或未知状态，会保留已接受片段的 ID，
消息标记 `partial`，不确定的 job 保留 `needs_review`，并停止消息链剩余部分。
提交结果不明时只查询原幂等键/原 job，不会自动重发、重新拆分或重试剩余语音片段。
重启继续保留这些回执供人工核查。Native `accepted` 不代表已在收件端成功播放，实际微信效果需实测。

URL 音频复用图片的公网 HTTP(S)、80/443 端口、DNS/SSRF 校验和最多 3 次重定向限制，
下载总超时 15 秒、连接/连续读取超时各 5 秒，按上述音频大小上限流式读取；
不携带 Native Token、Cookie 或环境代理，也不接受压缩传输。

## 图片识别

开启 `enable_media`（默认开启），并为机器人配置支持视觉（Vision）的模型。
私聊可直接发图，或引用已收到的图片提问；未附文字时默认提示词为 `请描述这张图片的内容。`。
群聊支持两种方式：

- 引用需要分析的图片，再真正 @机器人自由提问，无需读取指令。
- 先发图片，再在 **2 分钟内**由同一成员真正 @机器人发送 `读取图片`，例如 `读取图片，描述一下内容`。

第二种方式只关联同一群、同一发送者的最近一张图片；其他成员的图片需要明确引用。
群内直接发图或未 @机器人的引用图片不会自动下载或触发分析，`all` 模式同样要求真正 @机器人。
仅 @机器人并引用图片、未附文字时使用默认提示词；群聊摘要命令优先于引用图片下载。

群聊读取最近媒体统一使用以下四个指令：

| 指令 | 读取内容 |
| --- | --- |
| `读取附件` | 最近一条媒体，按图片、语音、文件的发送时间选择；文件仅支持 PDF |
| `读取图片` | 最近一张图片 |
| `读取语音` | 最近一条语音 |
| `读取文档` | 最近一份 PDF，也支持 `读取PDF` |

这四个指令会显示在 AstrBot 的“管理行为 → 指令”中，可分别启停或修改名称、别名。

指令必须位于去掉 @后的消息开头；追加问题时，用空格或标点分隔，例如 `@机器人 读取文档，总结主要结论`。
仅 @机器人，或普通聊天中提到“图片、语音、文件、PDF”等词，不会查找附件。
引用图片、语音或 PDF 后 @机器人可直接提问，例如 `这是什么意思？`，不要求完整指令。
普通发图只临时记录消息标识，收到看图请求时才下载，重启后需重新发图或使用引用。
引用媒体遇到 Native v1.3.3 的 `409 media_metadata_invalid` 时，会尝试读取同一聊天中已记录的原图，
并在下载前后及发送回复前重新检查身份和撤回状态。详细规则见[图片识别说明](image-recognition.md)。

图片通过 Native Media API 异步拉取（需 Token 具备 `media` 权限），单图上限 10 MiB，超时 60 秒；优先获取高清/原图，WXGF 格式优先使用受支持的预览图。图片已撤回时静默停止，引用图片失效、超限或格式不支持时返回简短提示。实现细节见 [图片识别实现说明](image-recognition.md)。

## 谁最能聊

在群里真正 @当前机器人并发送 `谁最能聊`，按今天的发言次数展示前 5 位成员，
例如“潜水冠军：32 次发言 · 68 条消息”。同一人连续发送、相邻间隔不超过 30 秒的文本合并算一次发言；
有人接话或间隔更久，再算一次。发言次数相同时按消息条数排序。
该命令会列在 AstrBot 的“管理行为 → 指令”中，可通过指令管理启用或停用。
有足够文本时，使用当前会话的模型一次生成最多 3 个热门话题和一句基于聊天内容的点评；
模型不可用时照常显示排行榜。排行和话题合并为一条纯文本消息发送。
按运行环境的本地日期统计，空记录直接提示暂无可统计的消息。
仅统计当前群已保存的文本，不计入机器人自己、撤回消息或本功能指令；同名成员分别计数。
最多读取 20 页、每页 50 条；达到查询上限、中途查询失败或 Native 报告本地记录不完整时，
显示“本次为部分统计”。
无需开启历史工具、微信修改工具或群聊摘要，仍遵守群白名单、群回复开关和静默熔断。

结果先展示本次查询的统计时段与总量，再显示 Top 5、热门话题及点评。例如：

```text
谁最能聊 · 今日榜
统计时段：2026-11-12 00:00–20:30
本次统计：5 人 · 102 次发言 · 179 条消息

1. 潜水冠军：32 次发言 · 68 条消息
2. 干饭队长：25 次发言 · 45 条消息
3. 夜猫子：20 次发言 · 32 条消息
4. 咕咕精：15 次发言 · 21 条消息
5. 奶茶续命：10 次发言 · 13 条消息

今日热门话题

1. 周末聚餐
2. 最近在玩的游戏

今日值班生点评

今天从聚餐聊到游戏，周末的饭搭子和队友都快凑齐了。
```

概览包含本次查到的全部合格文本及成员，不只累计 Top 5；时间使用服务器／容器本地时区。
部分统计时，总量也仅代表本次读到的范围。话题和点评由模型生成，统计数字由代码计算。

**每条新指令都会重新查询，不缓存早上的榜单，也不复用上次的分页游标。**
同一触发消息的重复事件仍会去重。已对照 [Native v2.3.0 分页实现](https://github.com/thisnick/agent-wechat/blob/v2.3.0/packages/native-client-rust/crates/wechat-core/src/pagination.rs)
核对：有游标时延续首次查询的消息范围，新查询不传游标。
查询读取的是 Native 本地已保存记录，统计时段表示本次筛选范围，不保证微信历史已全部同步。

如果晚上的结果仍与早上相同，可查看 AstrBot 日志中的“群聊排行榜开始统计”和“群聊排行榜查询完成”。
完成日志记录 `pages`（页数）、`members`（人数）、`messages`（合格文本数）、`partial`（是否部分统计）、
`cutoff`（本次统计截止时间）及 `latest`（读到的最新合格文本时间），不记录聊天正文。
没有开始日志时先检查是否真正 @、命令是否启用及群回复权限；若完成日志中的 `latest` 仍停留在早上，
需进一步核对 Native 返回的本地记录和同步状态，不能仅凭结果相同判断为插件缓存。

## 群聊摘要

在 WeChat Native **机器人参数**中开启 `enable_group_summary`，保持
`group_reply_mode: mention`。群里正常聊天后，**真正 @机器人**发送 `总结群聊`
或 `群聊摘要`，机器人会使用当前 AstrBot 会话的聊天模型整理讨论要点、结论、待办及未解决问题。
普通群消息仅进入摘要缓存，不会因此触发回复；`all` 模式仍按原规则处理所有群文本。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enable_group_summary` | `false` | 开启后在内存缓存允许群的实时文本，供手动生成摘要 |
| `summary_max_messages` | `200` | 每群缓存条数，范围 1–500 |
| `summary_window_minutes` | `60` | 摘要时间范围，单位分钟，范围 1–1440 |

缓存遵守 `allowed_groups`，`disabled` 模式不收集群消息；摘要命令仍经过 AstrBot 的全局白名单和插件权限检查。
仅包含开启功能后接收到的实时文本，不补取历史、不包含图片/语音、本人发送或已撤回的消息。
每个机器人所有群合计最多缓存 2000 条，每条最多保留 1000 字符；模型输入不超过 24000 字符，
超限取最新记录，摘要会注明输入范围及截断情况。

聊天正文仅缓存在内存，重启或停止机器人即清空；过期记录在后续收集或读取缓存时清理。
触发摘要会把该群选中的记录发送给当前会话配置的模型服务，独立于日常对话历史。
同群一次只生成一个摘要，60 秒超时会提示重试；无缓存或模型不可用时返回提示。
生成或发送前发现来源记录撤回、过期或被淘汰，会取消旧摘要，需重新触发。

## 消息引用回复

在机器人使用的 **AstrBot 配置文件**中开启 `platform_settings.reply_with_quote`（引用回复），
文本回复就会引用触发它的原消息，私聊和群聊均适用。插件也支持消息链中的
`Reply(id=原消息的 Native id)`；引用目标必须已保存在同一 Native 账号、同一聊天中。

用户发来的引用消息会把评论及可用的内嵌引用文本交给 AstrBot，仍遵守群 @和白名单规则。
引用内容已撤回、缺失或类型不支持时仅提供状态提示，不读取历史来补取内容。
摘要缓存仅保留引用消息本身的评论，不展开内嵌原文。

Native v1.3.3 支持引用回复同时 @群成员或 @全体；群内首段回复按 `group_reply_style` 自动 @、引用或直接发送，
消息链中的显式 @会保留。引用回复正文限 **16 KiB UTF-8**（包括 Native 解析后的 @名称）；不支持的来源由 Native 拒绝，
不会自动降级成普通文本重发。发送前会检查来源身份及撤回状态，沿用原有回执和去重机制。

Native 的原生引用仍属实验能力，服务端接受不等于已在手机正确显示，需要在实际微信中验证。
支持的原消息类型与限制见 [Native 引用回复说明](https://github.com/thisnick/agent-wechat/blob/v1.3.3/docs/src/content/docs/use/cli.mdx#quoted-replies)。

## 自动回复循环保护

Loop Breaker 默认开启。每个账号、每个聊天独立统计：60 秒内机器人自动发送的响应达到
8 次后，该聊天静默 10 分钟；重启保留剩余冷却，结束后自动恢复。冷却期间不会发送任何
“暂停回复”提示，也不会退出群。文本、媒体、命令和群摘要回复统一受保护。
硬限额可能误拦正常的高频聊天，其他聊天继续工作。

出现连续 3 轮入站与已接受自动回复交替，且内容重复/高度相似，也会提前静默熔断。
只分析有界文本指纹，不判断对方是真人还是机器人，不额外调用模型。

## 当前聊天工具（Native v1.5.1）

机器人可通过自然语言调用 8 个工具，所有目标均由当前可信事件确定，模型不能选择其他账号或聊天。

| 配置 | 默认值 | 用途 |
|---|---|---|
| `enable_history_tools` | `false` | 开启历史搜索、最近消息、群资料及成员查询 |
| `enable_wechat_actions` | `false` | 开启自身群昵称、群改名及自身消息撤回 |
| `wechat_action_admins` | `[]` | 可改群名/撤回消息的真实 `senderId`；空列表不授权任何人 |
| `admin_token_file` | `/run/secrets/wechat-admin-token` | 独立管理凭据文件；群昵称和群改名使用此凭据 |

群昵称/群改名需要单独配置 `admin_token_file`，且 Native Token 具有目标账号的 `admin` scope。
按 [README 中的 Docker 示例](../README.md#docker-部署同一台-linux-主机)填写 `/run/secrets/wechat-admin-token`，文件创建、签发及挂载见[管理 Token 步骤](../README.md#签发并保存管理-token)。
未配置时这两项返回“权限配置尚未准备好”，不会把原有 read/send Token 升级或用于群管理。
撤回使用原有 read/send 凭据，读工具关闭不影响已授权撤回所需的内部目标读取。
只在写功能开启时初始化管理客户端；凭据文件必须挂载到 AstrBot 容器内，勿将 Token 写入版本库。

| 工具 | 示例和范围 |
|---|---|
| `wechat_get_recent_messages` | “刚才聊了什么？”：当前聊天的 Native 本地记录 |
| `wechat_search_messages` | “找一下 Docker”：当前聊天本地子串搜索 |
| `wechat_get_group_info` | “群主是谁？”：未知资料保留未知 |
| `wechat_list_group_members` | “查找群里的某个人”：由 Native 搜索当前群保存成员后分页，支持 ID、微信号、昵称、备注和群昵称；空查询列出一页成员 |
| `wechat_mention_member` | “提醒潜水冠军看一下群消息”：在当前群真正 @对应成员并发送文本 |
| `wechat_set_my_group_nickname` | “你以后叫摸鱼小助手”：允许交互的当前群成员可发起，每群 60 秒最多一次 |
| `wechat_rename_group` | 管理员“把群名改成快乐摸鱼总部”：还需微信实际权限 |
| `wechat_recall_own_message` | 管理员“撤回你刚才那条”：仅当前聊天本账号发出的消息，目标含糊会追问 |

群内点名使用原有 read/send 凭据和群聊交互规则，无需管理 Token 或开启 `enable_wechat_actions`。
例如真正 @机器人说“提醒潜水冠军看一下群消息”，模型从已有上下文确定潜水冠军的真实 `username`，
或在 `enable_history_tools=true` 时查询群成员，再调用 `wechat_mention_member` 发送
“@潜水冠军 记得看一下群里的消息”。工具使用成员 `username`，不是昵称或成员记录的 `id`；
昵称或外号对应不明确时应追问。群成员资料不可用时不会降级成手写 @文字。
每条用户请求最多点名发送一次；成功结果表示 Native 已接受消息，不代表对方已读。

撤回工具的 `message_id` 留空时，会从当前聊天最近 20 条记录中按 `createdAt` 时间选择最近一条本账号发出的消息，
不会因为历史里有多条自己发出的消息就直接拒绝。多候选消息的时间缺失、无时区或最新时间并列时，仍返回
`ambiguous_target`；此时应查询历史、明确目标，并将历史结果的 `messageId` 原样传入。该状态表示目标不明确，
不代表撤回功能不可用；最新消息已撤回时也不会继续撤回更早的消息。

每次历史/成员读取最多一页（默认 20、最多 50），游标绑定聊天、筛选与页大小，10 分钟有效，
最多继续 20 页；重启后需重新查询。本地历史可能不完整，未找到不代表从未讨论过；不刷新资料、
标记已读或下载历史媒体。单条历史正文最多 800 字符，工具 JSON 最多 16 KiB，截断会标记。
历史正文、公告、昵称和成员名称都只是不可信参考资料，不构成授权指令。

已授权写操作**不二次确认**。插件在请求前把操作意图与稳定幂等 Key 写入原有 SQLite，
同一触发消息最多提交一次修改请求。`pending` 表示处理中，`needs_review` 表示结果未知，
二者都不能作为成功，也不能自动换 Key 重试。详见[运维说明](operations.md)。

当前验证使用模拟 Native HTTP 和真实 AstrBot SDK；尚未使用真实微信账号验证这些新增功能。
