# 群聊拍一拍回应设计

状态：用户已同意直接实施并负责部署调试，要求节省 token、仅保留 5 个测试。插件与 Native 补丁已实现；Native 编译、镜像构建和真实微信验证交由部署环境完成。

## 版本基线

- 用户确认当前 Native 为 v2.2.1，本功能应以该版本的实际接口为依据。
- 当前仓库 README 和 metadata.yaml 仍声明适配 v1.5.1；这属于仓库文档基线，不能据此认定用户部署版本。

## 已确认行为

- 仅响应群成员拍机器人；忽略成员互拍、机器人拍别人和自己拍自己。
- 沿用机器人现有人格，由模型生成简短回应。
- 回应前先读取拍一拍发生前的一条消息，供模型参考；支持文本、图片和语音。
- 图片使用实际图像供模型识别；语音复用用户已配置的语音转文本模型，转写后供模型参考。
- 参考消息可以来自同群任意成员，不限于拍一拍发起者；排除机器人自己发送的消息。
- 参考消息的时间边界是拍一拍发生前，不能用拍一拍之后新到达的消息替代。
- 跳过机器人自己的消息和暂不支持的消息类型，向前找最近的可用文本、图片或语音。
- 找不到消息、图片不可用、语音转写失败或读取失败时，仍按人格回应拍一拍，不编造上下文。
- 遵守群白名单和禁用群回复，在允许的群里无需 @；同群 30 秒最多回应一次。
- 用户接受构建、部署修改后的 Native，并通过部署日志和真实群操作迭代修正。

## 方案与取舍

已选择修改 Native 并接入插件的方向。Native 提供结构化真实身份，插件负责模型回应；复用现有消息提交、读取和发送链路。匹配“拍了拍”展示文案无法可靠区分昵称、发起者和目标，不作为实现方案。

上下文采用插件先读取、再调用模型的方式，保证回应前已经准备参考内容。让模型自行调用现有历史工具不能取得真实图像或音频，也不能保证每次先读取，不适合已确认需求。

## 建议默认值（随本设计一并审阅）

- 新增 enable_group_pat_reply，默认 false；开启后才响应拍一拍，避免升级后自动改变原有行为。
- 群白名单、disabled 和循环熔断优先于拍一拍开关；mention/probability 模式下，合格拍一拍视为直接唤醒。
- 会话归属拍一拍发起者，沿用 unique_session；参考消息作者不改变会话和工具权限主体。
- 沿用 group_reply_style：mention 时 @拍人者，plain 时直接发送。quote 模式因拍一拍系统消息不能作为原生引用目标，回退为直接发送，不引用另一位成员的参考消息。
- 历史查找每页 50 条、最多 20 页，不另设消息年龄上限；超过查找边界则按没有参考消息处理。这些是内部边界，不增加额外配置项。
- 冷却从本群开始处理一次合格拍一拍时计算，30 秒内后续拍一拍不再读取历史或调用模型；进程内按群隔离，重启不恢复此短期冷却，已有持久化循环熔断仍保留。

## Native 消息契约

建议保留 message.committed，不新增独立 SSE 消息通道。对已严格识别的拍一拍，在 GET /messages/{id} 和群历史列表的消息对象中增加可选 pat 字段：

```json
{"pat":{"actorId":"wxid_actor","targetId":"wxid_target"}}
```

此处为拟新增契约，不是 v2.2.1 已有接口。账号、群、稳定消息 ID、serverId、createdAt 和 origin 继续由现有消息或提交事件提供。识别成功时，senderId 为已验证的 actorId，direction 按 actorId 与当前账号身份确定；未识别的普通系统通知继续保持 senderId/direction 为空。

初版只处理有已知结构和测试样例支持的格式：sysmsg/pat，以及 appmsg 拍一拍 subtype 62 的已证实结构。每种格式分别校验必要字段、群与参与者身份，拒绝缺失、冲突、多义或无效 XML。不能用传输层 peer 替代 actorId，也不从模板文字反推身份。

10002 的识别必须在现有同步类型拦截前执行；只有确认为拍一拍且可按现有官方消息布局正确投影时才放行。未知 10002 保持现有行为。解析使用现有 roxmltree 防护，不启用 DTD，不返回原始 XML。

## 插件处理流程

1. 开关开启、实时入站、群权限允许、目标为当前机器人、发起者不是当前机器人、时间有效且未处理过时，接受拍一拍。
2. 在按群的既有并发保护中检查并占用 30 秒冷却，复用消息身份去重及回执状态；重放和重复事件不再次调用模型。
3. 读取当前群历史，排除机器人、已撤回、拍一拍、系统通知及未支持类型，选择拍一拍之前最近的普通文本、直接图片或直接语音。
4. 优先用拍一拍在 Native 历史顺序中的位置限定“之前”。若无法定位，只接受 createdAt 严格早于拍一拍的消息；时间缺失或无法确定先后时不猜测。不能把处理期间新到达的消息当作参考。
5. 文本按有界参考资料传入；图片通过现有 fetch_image 读取实际图像，遵守已有大小和格式限制；语音通过 fetch_voice 读取标准 WAV，用拍人者会话配置的 STT 转写。保留拍一拍提示，不能让 ASR 输出替换真实触发语义。
6. 将参考内容明确标为另一条群消息，交给现有人格模型生成简短回应。参考资料不是当前发起者新下达的指令，不授予参考消息作者任何操作权限。
7. 参考读取或转写失败时不换成更早的另一条内容；按没有可用上下文回应拍一拍。enable_media 关闭或视觉/STT 能力不可用时也走该回退。
8. 沿用原发送核验和幂等回执。发出前核对拍一拍源消息身份与 pat.actorId/targetId；参考消息被撤回时丢弃参考上下文，不能发送基于已撤回内容生成的回应。

## 部署日志与迭代

Native 记录：候选类型/子类型、解析分支、必要字段是否存在、群是否匹配、发起者是否自身、目标是否自身，以及有限枚举的拒绝原因。插件记录：事件接收、准入/冷却原因、参考类型、媒体或 STT 结果、模型与发送结果；用已有消息 ID 关联两端。

不记录 Token、原始 XML、消息正文、图片/音频内容、转写正文或完整模型提示。未知格式记录结构诊断和固定错误码，不能把原文写入异常日志。用户部署后按四类群操作采集结果：他人拍机器人、成员互拍、机器人拍别人、自己拍自己；再分别验证文本、图片和语音上下文。

本地先验证已知样例及模拟链路，再构建部署首版，通过上述日志核对真实投影并修正格式差异。不能把“部署后调试”视为跳过可执行的本地测试；未经真实微信测试不声明已验证真实收发。

## Native v2.2.1 接入核实

精确核查 v2.2.1 tag 的消息契约、系统消息归一化、同步投影和 SSE 入口，未发现专用拍一拍事件、解析器或发起者/被拍者字段。普通 message.committed 事件只给出消息 ID、聊天 ID、来源和投递方向；SSE 不补充拍一拍身份。

Native v2.2.1 对系统消息类型 10000/10002 清空发送者和方向；10000 只保留符合条件的纯文本，系统 XML 不返回。不能排除拍一拍作为普通系统通知出现，但没有真实报文证明它必定投影为这种消息，也没有可靠的身份字段供插件识别谁拍了谁。

## 已核实的接入约束

- 当前仓库声明适配 Native v1.5.1；用户实际部署为 v2.2.1。当前插件普通入站只处理 message.committed，并读取完整消息校验账号、聊天和消息身份。
- 当前分类要求实时、入站、非自身且有发送者身份；不支持的系统消息类型会被忽略。
- 当前已有按消息身份持久化去重、群白名单、群回复禁用和循环保护，应在接入方案确定后明确复用方式。
- NativeClient.messages 支持按当前群读取历史，但当前封装没有 before 或排序参数，不能直接假定 items[0] 就是拍一拍前的消息。
- NativeClient.fetch_image 和 fetch_voice 可按历史消息 ID 读取图片及标准 WAV；convert_message 支持 Image 和 Record，现有语音流程交由 AstrBot ASR 转写。
- 现有历史读取工具只输出媒体占位符，不交付图像或音频；不能仅靠调用该工具实现媒体上下文读取。
- Native v2.2.1 的公开 NativeMessage 契约没有拍一拍发起者和目标字段；profile.rs 的归一化逻辑及测试明确清空 10000/10002 的发送者和方向，不返回系统 XML。
- sync_projection.rs 对一般 10002 不生成普通消息投影；未知控制消息只报告受限的 account.control_observed，不公开原始内容。message.committed 和 SSE 也不补充拍一拍身份。
- 未取得真实拍一拍报文，不能断言当前微信一定以 10000 或 10002 投递拍一拍。已核实的公开契约不足以实现可靠身份识别，不能假定可由展示文案识别。
